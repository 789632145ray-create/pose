## 第3章 使用工具與技術

本專題以行動裝置即時姿勢偵測為核心，結合本機骨架分析、雲端帳號與 AI 姿勢品質辨識。開發與執行所使用之工具與技術整理如下。

| 項目 | 內容 |
|------|------|
| 作業系統 | macOS（開發）、iOS（執行） |
| 程式開發工具 | Xcode、Visual Studio Code |
| App 開發語言 | Swift |
| 前端介面技術 | SwiftUI |
| 姿勢偵測 SDK | QuickPose（相機／影片全身骨架） |
| 本機資料庫 | Realm（`pose.realm`） |
| 後端開發語言 | Python |
| 後端框架 | FastAPI |
| 容器與部署 | Docker、Railway |
| 雲端資料庫 | MongoDB Atlas |
| AI／機器學習 | scikit-learn RandomForest（`pose_quality_model.joblib`） |
| 安全與權限 | Keychain（Token）、相機／相簿權限、PBKDF2 密碼雜湊 |
| 其他設定 | `Info.plist`：`QuickPoseSDKKey`、`PoseServerBaseURL` |

### 3.1 技術選用說明

**行動端（iOS）**  
以 SwiftUI 建置使用者介面，涵蓋登入、即時偵測、影片分析、歷史摘要與會員管理。姿勢骨架由 QuickPose SDK 自相機或本機影片擷取，每幀可取得全身關節座標，供後續特徵分析與資料儲存使用。

**本機儲存（Realm）**  
偵測過程中產生之關節節點與分析摘要需即時寫入裝置，並支援非阻塞背景寫入，故採用 Realm 作為本機持久化方案，取代舊版 JSON／SQLite 儲存方式。

**雲端後端（FastAPI + Railway）**  
帳號註冊登入、影格串流上傳、姿勢品質預測及標註資料管理，透過 FastAPI 提供 REST API，並以 Docker 部署於 Railway，方便與 iOS App 以 HTTPS 連線。

**AI 模型（RandomForest）**  
姿勢品質採二元分類（good／bad）。特徵為 session 級統計（35 關節 × 平均／標準差 × x／y／z，共 210 維）。模型於 Mac 端以 `train.py` 訓練後產出 `joblib` 檔，再部署至後端供 `POST /predict` 即時推論。

## 第4章 專題規劃

本專題依照「需求分析、系統設計、系統實作、AI 功能整合、系統測試及成果驗證」進行開發。首先分析姿勢偵測與健康評估之使用情境，再規劃 App、本機資料庫、雲端 API 與模型訓練閉環。系統實作以 SwiftUI、QuickPose、Realm 為行動端主軸，並以 FastAPI、MongoDB Atlas、RandomForest 完成雲端與 AI 功能。

### 開發法

1. **需求分析**：確認相機／影片偵測、即時建議、步態統計、帳號與歷史紀錄等需求。  
2. **系統設計**：規劃八大功能模組、資料流與本機／雲端儲存分工。  
3. **系統實作**：完成登入、偵測 HUD、節點資料庫、摘要歷史與 API 串接。  
4. **AI 整合**：串接姿勢品質模型與即時預測 HUD。  
5. **訓練閉環**：標註上傳 → 訓練 → 部署 → 驗證。  
6. **系統測試**：相機權限、離線規則分析、連線預測與帳號流程測試。  
7. **成果驗證**：以實際操作確認偵測、評估與建議輸出之可行性。

---

### 4.1 系統架構設計

本系統採用「使用者介面層、資料蒐集／特徵層、雲端後端層、AI／訓練層」之架構，並以本機 Realm 與雲端 MongoDB Atlas 共同支援資料持久化。

**使用者介面層**  
提供登入註冊、姿勢偵測主畫面、FPS／步數／品質 HUD、暫停與結束摘要、歷史查詢及會員資料管理。

**資料蒐集／特徵層**  
QuickPose 擷取每幀 35 個身體關節；經可見度過濾後進行肩、骨盆、軀幹、頭部對齊分析，以及左右腳步態偵測，並可組合成 ML 所需之 session 特徵。

**雲端後端層**  
負責帳號驗證、session 影格批次上傳、標註資料寫入 MongoDB，以及姿勢品質預測 API。

**AI／訓練層**  
自標註 session 訓練 RandomForest 模型，部署後供 App 即時呼叫；亦可持續以新標註資料重訓更新。

#### 端到端資料流（摘要）

1. 使用者於 App 啟動相機或選取影片。  
2. QuickPose 回傳骨架 landmarks → 本機寫入 Realm，並可串流至後端。  
3. 本機規則引擎產出對齊建議與步態事件；訓練模型模式下另呼叫 `/predict`。  
4. 偵測結束產生分析摘要並存入歷史；標註資料可上傳供後續訓練。

---

### 4.2 模組功能說明

主要分為以下八個功能模組：

**① 使用者端 APP**  
提供根畫面路由、帳號註冊／登入／登出、會員密碼與資料管理、QuickPose 簡易模式與訓練模型完整管線切換、相機即時偵測與影片上傳分析、伺服器位址設定。

**② 資料蒐集模組**  
初始化 QuickPose、以全身 overlay 擷取 35 關節（含 nose、shoulder_mid、hip_mid 及左右肢體點位）、非阻塞寫入 Realm，並可批次串流上傳至雲端。

**③ 特徵擷取模組**  
過濾低可見度關節；分析肩高低差、骨盆傾斜、軀幹側傾、頭部偏移；以 5 幀低通與骨盆歸一進行左右腳踝峰谷步態偵測；並產出 210 維 session 特徵供訓練與預測。

**④ AI 姿勢品質辨識模組**  
以 RandomForest 進行 good／bad 分類；App 透過 `POST /predict` 取得標籤與機率，並於 HUD 顯示信心百分比。

**⑤ 健康／姿勢評估模組**  
彙整即時姿勢問題、總步數、左／右步、平均步頻、左右平衡警示，以及各問題代碼於整段影片中的占比，並於偵測結束自動存歷史。

**⑥ 建議產生模組**  
偵測中提供對齊文字建議；暫停時提供休息提示；結束後輸出步態與問題摘要；並支援歷史查詢與刪除。

**⑦ 雲端後端服務**  
提供註冊、登入、變更密碼、開啟／上傳／結束 session、標註 poses 上傳、姿勢預測與健康檢查等 REST API。

**⑧ 管理／訓練流程**  
於 App 標註 good／bad 後上傳 MongoDB；於 Mac 執行 `train.py` 產出模型；再以 git push 觸發 Railway 重新部署，完成訓練閉環。

### 4.3 方法架構

系統方法架構對應四層與儲存基礎設施如下：

| 層級 | 職責 | 主要技術／檔案 |
|------|------|----------------|
| 使用者介面層 | 操作與即時回饋 | `RootView`、`LoginView`、`PoseDetectionView` |
| 資料蒐集／特徵層 | 骨架、步態、對齊特徵 | QuickPose、`PoseDatabase`、`PoseAnalysisPipeline` |
| 雲端後端層 | 帳號、串流、預測 API | FastAPI `main.py`、Railway |
| AI／訓練層 | 特徵工程與模型部署 | `train.py`、`pose_quality_model.joblib` |
| 本機儲存 | 節點與摘要 | Realm `pose.realm` |
| 雲端儲存 | 使用者與標註 session | MongoDB Atlas |

各層透過 App 內函式呼叫與 HTTPS REST API 完成資料交換，使系統同時具備即時偵測、本機評估、雲端帳號與 AI 品質辨識能力。

### 4.4 敏捷開發流程（建議）

**待辦清單**  
使用者登入與 Token 管理、相機／影片姿勢偵測、35 關節本機儲存、步態與對齊分析、即時／暫停／結束建議、歷史摘要、影格串流上傳、姿勢品質預測、標註與模型訓練部署。

**Sprint 1（基礎環境）**  
登入註冊、基本頁面架構、QuickPose 相機權限與簡易 overlay。  
成果：完成可登入並開啟相機骨架之環境。

**Sprint 2（核心偵測）**  
即時 HUD（FPS、步數）、本機 Realm 寫入、對齊建議與步態管線、影片上傳分析。  
成果：完成主要姿勢偵測與本機評估功能。

**Sprint 3（雲端整合）**  
session 串流、歷史摘要、會員管理、伺服器設定。  
成果：App 可與後端同步帳號與偵測資料。

**Sprint 4（AI 智慧功能）**  
標註上傳、RandomForest 訓練、`/predict` 即時品質 HUD、部署驗證。  
成果：完成姿勢品質辨識與訓練閉環。

**Sprint Review／Retrospective**  
每個 Sprint 結束後進行功能測試與展示，檢討相機權限、離線／連線行為、API 穩定性與模型準確度，並依結果持續改善。
